The two logs are files beside the world. They are not fields of `World`.

- `src/log/journal.ts`. `JournalEntry` is `{ correlationId, month, ts, effect, source }` with `source: "agent" | "engine"`. The line stores the effect tag. It does not store the reason.
- `src/log/intentlog.ts`. `IntentRecord` is camelCase: `{ callId, correlationId, month, ts, agent, status, reason }`. Status is `attempted | ok | rationed | refused | error`. `latestByCall` keeps the outcome.
- `src/log/reconcile.ts`. Joined by correlation id. An alarm is `write-without-reason` (an agent journal line with no ok or rationed intent) or `reason-without-write` (an ok or rationed intent whose correlation is missing from the agent journal). Engine lines have no intent record and do not alarm. `refused` is blocked. `error` with no journal line is neither an alarm nor a block. `rationed` is in the type and is not produced until a market exists.
- `src/bridge/harness.ts` is treasury's `runMutation`. Order: registry, then argument scope, then a non-empty reason, then `attempted`, then the command, then one outcome under the same `callId`. An empty reason, a missing command, and a scope violation are `refused` with no `attempted` line, and the command does not run. A gate refusal inside the command is `attempted` then `refused`. The journal does not grow in either case. The CLI never writes the reason. A read is one intent line, status `ok`, `correlationId: null`, reason `"read"`.
- `src/cli/refusal.ts`. `Refusal` is the process-edge exception. A gate refusal is a value everywhere else.
- `verify.sh` type-checks, runs the tests, runs `src/demo.ts` twice, and diffs stdout together with the concatenation of `demo-out/story/{world.json,journal.jsonl,intent-log.jsonl}` and `demo-out/month/...`. `.gitignore` ignores `demo-out/` only.

`absfc_core.py` is still in the tree and is not imported.

## Rulings

- `source` and `ts` are on the journal, and `ts` is on the intent record. The interface's `JournalEntry` names neither. Without `source`, an engine wage is indistinguishable from an agent commit that has no reason.
- Log correlation ids and timestamps come from the injectable seams in `src/log/ids.ts`. Domain ids (`World.nextId`) and `month` are fields of `World`. `RngState` is `{ seed, stream }`. The clock, the id source, the working directory, and the Part III parameters are not the store.
- The `--live` branch is in `src/demo.ts` (written with milestone 5). It constructs `realIds` and `realClock`, does not call them, prints `not implemented` to stderr, and returns 1 before any write. A live run must not be stamped with `fixedClock`.
- Do not edit `src/lib/algebra.ts`, `src/log/ids.ts`, or `src/log/ids_test.ts`. A root `deno fmt` rewrites the vendored algebra and the plan documents (`PLAN.md`, `LESSONS.md`, `plan-so-far.md`, `prompt-so-far.md`). Format only new TypeScript, and leave those four files out of the set.
- One worker. Its state is the world. Leaves are memoryless. There is no `fleet/consolidation.ts`. On a scripted run the intent log is a file beside the world. On a live run the harness transcript is a second register, `Δ(Transcript)`, and it is not a field of `World`.
- Amalgamation is two constructions. The invariant is that each of the five instruments sums to zero, and that each holder's flow column matches that holder's change in net financial assets. Inside a market, amalgamation is `tensorC`: every poster and every buyer answers. `productC` owes one reply and is not a market or a lottery. Lotteries draw from `RngState` after a tensor collects bids. Reconciliation is the auditor's join, and it is not the same construction as the sum.
